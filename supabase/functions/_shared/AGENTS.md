# Telephony rules

- Inbound phone forwarding defaults off per tenant/user and is changed through telephony-api after active membership and destination validation; why: receiving choices must not create unauthorized spending or forwarding loops.
- Real inbound advisors accept with a provider-signed digit before bridging; missed calls use persisted provider results, and database triggers deliver scoped, deduplicated alerts; why: voicemail, greetings, popup clicks and retries must not fabricate attended calls.
- Tenant inbound policy selects active-tenant recipients and gates personal opt-in; destinations resolve from current profile phones and signed acceptance claims the answering advisor; why: group routing must not bypass permissions or use stale custom numbers.- Advisor states change only via set_agent_status/agent_status_heartbeat; inbound routing rings only available advisors with a fresh heartbeat (no state row = legacy) while still notifying; why: auditable shift reports, no ringing during breaks.
- Call recordings download only through telephony-api recording_download (caller RLS, conversation-only, audited); why: provider URLs and credentials never reach the browser.
- Call analysis explicitly awaits recordAiUsage with the initiating user or call advisor and charge:false; entrypoints must not also auto-track it; why: provider callbacks need reliable attribution without duplicate logs or new plan charges.
- Typification suggestions reuse tenant/contact-authorized call results only for an active catalog match and unchanged note; editing notes requires explicit refresh; why: one analysis must not trigger repeated inference during typing.
